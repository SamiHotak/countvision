You are my senior engineer and product partner. We are building CountVision, a REAL product that businesses will pay for — not a demo. It is also my main computer-vision portfolio piece for Upwork.

PRODUCT
CountVision turns a business's EXISTING cameras into visitor and traffic numbers.
- Problem: shops, cafés, gyms, venues and parking operators don't know how many people or vehicles come, when, or how long they stay. They guess, count by hand, or buy expensive sensors.
- Solution: an on-site "edge agent" (laptop, mini PC, Jetson or GPU server) reads the cameras, detects and tracks people and vehicles, counts line crossings (in/out), measures occupancy, dwell time and queue length in zones, and sends ONLY numbers to a cloud dashboard with live counters, charts, alerts and reports. No video leaves the building.
- Why they pay: better staff planning, shorter queues, proof of visitor numbers, safety/capacity limits — without new hardware.
- Price idea: €29–79 per camera per month, or setup fee + monthly fee.

ARCHITECTURE
1. edge/ — Python service (later in Docker):
   - Inputs: USB webcam, video files, RTSP/IP cameras (auto-reconnect with backoff), HTTP/MJPEG.
   - Detector interface with implementations: Ultralytics YOLO (AGPL-3.0) and a permissively licensed model (RF-DETR or RT-DETR, Apache 2.0). Runtimes: PyTorch (CUDA), OpenVINO (Intel CPU), ONNX Runtime, TensorRT (later).
   - Tracking: ByteTrack via the `trackers` package (Apache-2.0; supervision's own ByteTrack is deprecated), class smoothing, minimum track length.
   - Analytics: line crossing with direction, polygon zones (occupancy, dwell time, queue length), per-class counts, speed estimate with 2-point calibration, heatmap.
   - Frame scheduling: target FPS per camera, adaptive frame skipping under load.
   - Output: events + 1-minute aggregates; local SQLite buffer when offline; heartbeat (FPS, CPU/GPU load).
   - Privacy: no frames leave the device by default; optional blurred low-res preview; snapshots only on request for configuration.
2. cloud/ — the SaaS app (from phase 3):
   - Backend: Python 3.12, FastAPI, SQLAlchemy 2 + Alembic, PostgreSQL with TimescaleDB, Redis, Celery workers + beat.
   - Frontend: Next.js (App Router) + TypeScript + Tailwind + shadcn/ui.
   - Platform basics: email/password + Google login, organizations, roles, invites, Stripe billing with plan limits (cameras per plan), audit log, emails, Sentry. Build these cleanly so they can later be reused for other products.
   - Product: sites, cameras, devices (pairing with a code/token), ingestion API (batched, idempotent, per-device auth), config editor (draw lines/zones on a snapshot, pushed to the edge), live counters (SSE), dashboards, alerts (email/Telegram/webhook), scheduled PDF/CSV reports, public API + webhooks, video-file analysis jobs, custom model training + deployment to devices.
   - Deployment: one Hetzner server in Germany, Docker Compose, Caddy (HTTPS), GitHub Actions CI/CD, nightly backups.
